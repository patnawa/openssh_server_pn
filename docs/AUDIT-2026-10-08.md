# Server and client GUI audit — 8 October 2026

The starting revision was `1d60e71107cd8808bab4642ade9dd5ab9ea038ea`
(product 10.5.5.0, Manager 2.2.1). The initial working tree was clean. This audit
examined the manager, client configuration and trust editing, background jobs,
Windows integration, installer feature selection, and release provenance. It
also examined the maintained native `AuthorizedKeysFile` formatting patch and
the project's native test pipeline. It does not establish the security of every
vendored OpenSSH or cryptographic implementation.

The follow-up implementation is tracked in [the improvement plan](IMPROVEMENT-PLAN.md).
A second review of the 10.5.7.0 / Manager 2.3.1 sources, made the same day, is recorded in
[AUDIT-2026-10-08-FOLLOWUP.md](AUDIT-2026-10-08-FOLLOWUP.md). Among other things it found that

The initial changes were distributed as unsigned r3 testing previews. The 10.5.7.0 /
Manager 2.3.1 follow-up at `098e124` repairs the later installer-fixture failures.

and verified on **8 October 2026**, with Manager Latest. Historical results apply to

## Findings and consequences

| Priority | Finding | Concrete consequence | Correction |
|---|---|---|---|
| High | Client trust deletion used a displayed line index after rereading the file. Client config saves lacked an edit snapshot. | A concurrent `ssh` append or another editor could cause the GUI to delete a different key or overwrite a newer configuration. | Content snapshots, explicit conflict errors, guarded atomic replacement, and regression tests that change the file between display and save. |
| High | The profile editor reduced repeated `IdentityFile` settings to one and appended new profiles behind broad defaults. | The saved profile differed from what `ssh` actually used; an intended identity or host-specific value could disappear. | Preserve and edit identity lists; account for first-value precedence; compare representative results with real `ssh -G`. |
| High | Server inspection and blocking assumed one port, omitted Include resolution, and treated failed peer enumeration as an empty result. | Some listeners were unprotected, while a legitimate connected address could lose its exemption during an inspection failure. | Resolve configuration with `sshd -T`; combine configured and running listener ports; require complete IPv4, IPv6 and process-owner inspection before automatic blocking. Surface the reason for deferral. |
| High | Rollback depended on a timer in the GUI. | Killing the manager, losing the desktop session or rebooting could leave an unconfirmed configuration active. | A protected persistent transaction and separate SYSTEM recovery task, with boot and time triggers, expected-content guards, and retryable recovery. Configuration and firewall changes belong to the same recovery decision. |
| High | The atomic write helper fell back to overwriting the destination. | A replacement failure could destroy the original configuration rather than leave a recoverable error. | Same-directory flushed temporary writes and atomic replacement only; failure preserves the original bytes. |
| High | Client-only MSI selection still reached server cleanup logic. | Installing a client could stop or change an existing server and interrupt sessions. | Gate cleanup on resolved server component actions; include the normal-user GUI in the shared feature; verify the client-only case in an isolated installer scenario. |
| High | Authorized-key discovery lost quoting, handled only one path, or guessed a fallback path after failure. | A key could be written to a file the server never reads, giving a misleading authorization result. | Preserve all configured paths and token semantics, fail explicitly when discovery is unavailable, and quote the native effective-settings dump so it can round-trip. |
| Medium | Transfer IDs used rounded time and partial transfer batches lost prior context. | Distinct transfers could merge, zero-byte files disappear, or peers and users be misattributed across polling and day boundaries. | Event-backed identities, a persistent incremental parser, checkpoint anchors, versioned archive rows, and split-stream/replay regression tests. |
| Medium | A cleared or wrapped event log was not a durable part of checkpoint state. | Missing history could silently look like a complete report. | Detect generation and retention gaps, persist their evidence, and display the gap and backlog in agent health. |
| Medium | Notification transitions were consumed before successful delivery, with network calls under the shared state lock. | A temporary SMTP/webhook failure could permanently lose an alert and delay other background work. | A durable per-destination outbox, leased delivery outside the lock, bounded retries, receipts, and explicit retry after settings are corrected. |
| Medium | The elevated server window also owned the user's client workspace. | With over-the-shoulder UAC, the administrator's profile could be mistaken for the original user's; client configuration may execute commands. | An `asInvoker` client workspace, explicit elevation for server administration, and a launcher using the desktop shell's user token and environment. |
| Medium | Release jobs could package a committed executable instead of the source they had just tested. | Source review and test results did not establish which manager bytes reached the release. | Pin compiler and reference packages by SHA-256; build once, test that artifact, package it, then verify extracted payload hashes. Signed tag builds fail when their signing requirements are absent. |
| Medium | Fifteen tabs, scrolling save controls and implicit background-job status obscured operation state. | Users could miss unsaved settings, delivery failures or history gaps. | Grouped navigation with a compact selector, persistent save footer, pending-change text, and explicit agent health. |

## Module design

The important seams are file transactions, resolved server state, journal consumption,
notification delivery and the normal-user client workspace. Their callers should ask
for a verified result or receive an explicit failure. A failed native query must not
be converted into a success-shaped empty collection.

`ClientFileSnapshot` owns conflict detection for client files. `ConfigurationTransaction`
owns server writes and their dependency checks. `ConfigurationRecovery` owns the
durable restart decision. `ServerState` owns endpoint resolution. `TransferJournal`
owns parser continuation and event-log identity. `NotificationOutbox` owns delivery
state and retry semantics. These modules let tests reach the same behavior as the GUI
and scheduled jobs without requiring live service or firewall mutations.

The manager remains a WinForms application targeting .NET Framework 4.5. Extracting
the client workspace and operation runner reduces the size and responsibility of
the main form without introducing another UI framework. Native COM work needs an
STA worker; UI changes must resume on the UI thread. Cancellation should stop
read-only work at explicit points. It must not imply that a partially completed
service or configuration mutation was undone.

Hosted runs exposed two atomic-write details: replacement could change the primary
group, and its ACL merge could turn inherited entries into explicit duplicates on
Windows Server 2022. The latter changes how later parent-folder permissions apply.
Scratch reproductions and regressions cover both cases. The transaction now stages
the original streams and supported metadata in a secured temporary file, verifies
owner/group/DACL and inheritance flags, writes and flushes the new default stream,
then performs a same-directory rename with replacement and no copy/delete fallback.
It preserves creation time and supported attributes, and refuses read-only or
reparse-point files and metadata it cannot preserve. This avoids the documented
[ReplaceFile merge behavior](https://learn.microsoft.com/windows/win32/api/winbase/nf-winbase-replacefilew);
[same-volume rename retains the source ACL](https://devblogs.microsoft.com/oldnewthing/20060824-16/?p=29973).

The hosted build also exposed different compiler inputs caused by LF versus CRLF
checkouts. Builds now normalize the compiler's text inputs, and the reproducibility
check compares separate checkouts with different newline/BOM formats and paths.

## Behavioral limits to preserve

- Outbox retries can produce duplicate delivery if a transport accepts a message
  and the process exits before recording its receipt. Automatic retries stop after
  12 failed attempts; exhausted entries remain available for explicit retry (from Manager 2.3.2,
  for 30 days and at most 200 per destination; the number discarded is shown in agent health). This
  does not guarantee eventual delivery. Delivery IDs help identify duplicates;
  arbitrary SMTP and webhooks cannot provide exactly-once delivery on their own.
- Event-log retention can remove events before the collector sees them. A persisted
  gap is honest evidence of incomplete history, not a reconstruction of those events.
- External configuration changes during a recovery transaction are not overwritten
  silently. Recovery reports the conflict so an administrator can resolve it.
- An effective-settings preview executes the client's configuration semantics,
  including possible `Match exec` commands. It therefore belongs in the normal-user
  workspace.
- The existing system-DPI mode is retained for the .NET 4.5 compatibility baseline.
  Off-screen scale tests check layout; they cannot prove physical mixed-monitor or
  screen-reader behavior. A future PerMonitorV2 migration needs a separate runtime
  compatibility decision and desktop acceptance tests. Microsoft's built-in enhanced
  WinForms DPI support starts with [.NET Framework 4.7](https://learn.microsoft.com/en-us/dotnet/desktop/winforms/high-dpi-support-in-windows-forms).

## Verification and release decision

Focused client regressions, native parser/dumper round trips, journal replay/outbox tests,
recovery fault injection, package extraction and deterministic manager builds are automated.
The original [preview product run](https://github.com/patnawa/openssh_server_pn/actions/runs/37737760283)
failed three installer-acceptance categories. Source `098e124122438ae9b123af881a3897ba6487d8b4`
repairs their demonstrated fixture causes without weakening the behavior assertions:

- Six installed window checks inspected controls before posted asynchronous startup
  finished; a direct background test also lost its WinForms context after a standalone
  message pump. Both cases now have regressions and await the intended UI state.
- The recovery child inherited PowerShell 7 module precedence and could not resolve
  Windows PowerShell commands. The corrected child prioritizes its own module paths.
- The wizard check misread the result of scheduling an asynchronous MSI action. It now
  recognizes those records while retaining actual launch, user-identity and request checks.

Local checks and the [hosted manager run](https://github.com/patnawa/openssh_server_pn/actions/runs/37773127926)
pass **164 unit tests, 49 GUI checks and 13 installer-fixture checks**. The six original
isolated window cases also pass. Reviewed manager SHA-256:
`EF1B84B5A1D5D3FE63579CEB50E614795DE77C95B1090042BE044B81B3090EA3`.

The [full product run](https://github.com/patnawa/openssh_server_pn/actions/runs/37773128497)
passed all **14 expected jobs**, with tag-only signing/release jobs intentionally skipped
for the branch build. x64/x86/ARM64 native build, unit, crypto and configuration gates
passed. All four installation lanes (Server 2022, Server 2025, PowerShell 2.0 and Windows 11
ARM64) passed **212/212 installed self-tests**, actual SYSTEM process-termination recovery,
wizard launch, client-only coexistence, authentication, SSH/SFTP, upgrade, repair, rollback
and uninstall. The release-files gate passed. Informational Pester: **159 passed, 0 failures,
1 ignored**.

The owner-authorized regular unsigned `release-v10.5.7.0` and `release-manager-v2.3.1`
releases were published on **8 October 2026** from the exact accepted hosted branch artifacts.
All 11 product and 8 Manager assets were downloaded afresh before publication and publicly
afterward; all 19 hashes matched the accepted staging files. Both regular-release flags and
Manager's Latest destination were verified. Hosted
origin does not provide an Authenticode signature or cryptographic attestation; the
signed `v*` / `manager-v*` workflow gates stay unchanged.

Actual reboot recovery and pending-file replacement, the GUI click/confirmation recovery
flow, other-account UAC/client identity, and manual keyboard/screen-reader/mixed-monitor
acceptance remain pending. Hosted process termination is not evidence of those scenarios.
Signing remains pending an owner-supplied identity. The unrelated local VM and working
machine were not used for experimental installation. See [VALIDATION.md](VALIDATION.md)
and [the current evidence record](IMPROVEMENT-PLAN.md).
