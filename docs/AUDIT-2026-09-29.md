# Project bug audit — 2026-09-29

This audit focused on the Windows manager, its configuration and transfer logic, background
jobs, the installer helpers, and the manager build pipeline. It is not an exhaustive security
review of the bundled OpenSSH or cryptographic implementations. The working tree was clean
at the start. Changes remain uncommitted.

## Confirmed bugs fixed

| Area | Failure | Correction |
|---|---|---|
| Configuration | Editing an existing scalar below `Include` left the included value in effect. | Move the edited scalar ahead of the first Include while preserving its comment and repeatable directives. |
| Authentication | Choosing any enabled method could leave an included multifactor requirement active. | Write explicit `AuthenticationMethods any` when top-level Includes exist. |
| SFTP folders | Literal `%%h` was mistaken for a profile substitution and rejected or could not expand. | Parse percent tokens once and require a profile only for a real `%h`. |
| Partner setup | A drive root such as `C:\` became `C:`, producing drive-relative account paths. | Preserve the directory root when recovering it from the group rule. |
| Partner names | Names such as `CON` and `nul.log` passed validation although they cannot name ordinary Windows folders. | Reject reserved device names, including names with extensions. |
| Webhooks | Control characters other than newline/tab could produce invalid JSON. | Escape all JSON control characters. |
| Scheduled jobs | Watch and Daily could load the same state and overwrite each other's updates. | Hold a shared machine-wide mutex from state load through save, with bounded waits and abandoned-lock recovery. |
| Transfers | Two simultaneously open empty uploads could both disappear from history. | Track open files separately within each session. |
| Transfers | Interrupted transfers emitted `forced close` and lost their recorded byte counts. | Parse forced closes as transfer records. |
| Transfers | A denied directory operation could be attributed to an earlier file open. | Track the preceding request separately from active files; retain it through known verbose/debug status explanations. |
| Installer rollback | Global Port values incorrectly displaced explicit ListenAddress ports. | Use each explicit address port and expand global/default ports only for portless addresses. |
| Installer editing | `Match=all` was not recognized, allowing a global Port to be inserted in a Match block. | Recognize the equals delimiter in both port editing and extraction. |
| Manager build | `-Csc` was ignored because `$csc = $null` overwrote the case-insensitive parameter. | Keep the resolved compiler in a separate `$compiler` variable. |

Each fix has regression coverage. The original manager baseline passed 74 tests; new failures
were reproduced before the relevant fixes. An independent review also caught a verbose-log
regression in the transfer change, which was corrected and covered before delivery.

## Verification

- Manager builds with warnings treated as errors; the tracked executable is rebuilt.
- Manager unit suite: 85 passing tests, including 11 added cases.
- Installer helper suite: 126 checks passed under Windows PowerShell 5.1. This also checks the
  embedded script variants and their command-line size limits.
- Compiler-selection suite: two checks passed under Windows PowerShell 5.1; CI now runs it.
- Configuration precedence was also checked with `sshd -T` using private temporary config and
  host-key fixtures, without changing the live configuration.
- Existing x64 native binaries: seven suites passed, totaling 686 tests. The eighth,
  `unittest-win32compat`, stopped at test 39 because symbolic-link creation lacked privileges.
  These binaries were not rebuilt during this audit.
- Non-elevated manager self-test: three failures from unavailable protected host keys and
  unauthorized security inspection; eight additional cases explicitly skip without elevation.
  This does not constitute a passing elevated integration run.
- `git diff --check` passes.

## Remaining work and limits

1. Run elevated `--selftest`, `--keytest`, and `--authtest`, and the native symbolic-link tests
   in a disposable Windows test environment. Rebuild/package all architectures and exercise
   MSI install, upgrade, and rollback before release. No MSI was installed by this audit.
2. Investigate the client-only installation path: source inspection suggests the preinstall
   helper may stop/remove an existing in-box server even when only Client is selected.
   This remains a hypothesis requiring isolated MSI reproduction; no speculative fix was made.
3. The installer's text-only rollback port parser still does not expand Include files.
4. INFO-level transfer logs do not identify handles, so simultaneous opens of the same path
   cannot always be distinguished. The per-file fix covers concurrent distinct paths.
5. The mutex's cross-account ACLs and scheduled-task behavior require elevated integration
   coverage; unit tests exercise contention, release after exceptions, and abandoned ownership.

An optional read-only daemon probe in one audit worker was rejected by automatic approval
review with `blocked by policy` and no further rationale. That worker did not retry it.
