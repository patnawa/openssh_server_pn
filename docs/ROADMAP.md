# Improvement roadmap

Functions worth adopting from other SSH and SFTP servers, ranked by value and feasibility for a
server built on OpenSSH for Windows. Each item names the products that have it, how it can be
realised without touching `sshd` source code (through `sshd_config`, `authorized_keys` options,
OpenSSH certificates, Windows features, or the management GUI), and its status in this repository.
Items that would require changes to the `sshd` C code are listed at the end; they are out of
scope for a packaging fork and belong upstream.

Sources: the survey in [COMPARISON-BITVISE.md](COMPARISON-BITVISE.md) (Bitvise) and its
appendix on other servers (Tectia, VShell, SFTPGo, Cerberus, CrushFTP, Rebex Buru, Syncplify,
Apache MINA SSHD, wolfSSH, Dropbear, Pragma Fortress) and the upstream OpenSSH release notes,
all read on 2026-09-25.

Status legend: **Done** = available in this repository today; **GUI** = implemented in OpenSSH Server
Manager; **Config** = achievable now with documented configuration; **Planned** = candidate for
the next manager release; **Upstream** = needs the Windows port maintainers.

| # | Improvement | Seen in | How on OpenSSH for Windows | Status |
|---|---|---|---|---|
| 1 | **Rebase the Windows port on OpenSSH 10.5p1.** Upstream 10.3 to 10.5 (2026-04 to 2026-08) fix, on the server side: GSSAPI pre-authentication denial of service, incomplete `PubkeyAcceptedAlgorithms` enforcement for ECDSA keys, `internal-sftp` argument truncation after the ninth argument, `principals=""` matching, `restrict` now blocking tunnel forwarding, `ChannelTimeout` and `RekeyLimit` honoured inside `Match`; they add multi-file `RevokedKeys`, an `invaliduser` penalty class, `GSSAPIDelegateCredentials` and stricter transport checks. The Windows port (`latestw_all`) is at 10.2p1. | upstream OpenSSH | Done here: `src/` carries the maintainers' 10.3 merge plus our 10.4 and 10.5 merges (build 10.5.0.0, see CHANGELOG). Still to do: offer the merges upstream so the official port catches up. | Done (10.5.0.0) |
| 2 | **Brute-force defender with scores, ban time and escalation, visible in the GUI.** | SFTPGo Defender, VShell Deny Host, Cerberus auto-ban, CrushFTP hammering protection, Syncplify Protector, Buru lockout | `PerSourcePenalties`, `PerSourceNetBlockSize`, `PerSourceMaxStartups`, `MaxAuthTries`, `LoginGraceTime` are active in this build (checked by the Hardening tab). Next: the manager subscribes to the OpenSSH/Operational event channel, keeps a per-address score with an observation window and escalating ban time, and adds or removes scoped Windows Firewall block rules, with a safe list and manual unban. | Config now, GUI planned |
| 3 | **Per-user and per-group SFTP jails with permission presets** (read-only, upload-only drop box, full), several physical folders under one jail. | Buru path mappings, SFTPGo virtual folders, VShell virtual roots, Cerberus virtual directories | `Match Group sftp-only` with `ChrootDirectory`, `ForceCommand internal-sftp -d <start> -R` (read-only) or `-P remove,rmdir,rename,setstat` (drop box) or `-p <allow list>`; NTFS junctions (`mklink /J`) expose more folders inside the jail. A manager wizard would create the folder tree, set the ACLs `sshd` requires on the chroot root, and write the `Match` block. | Config now, GUI planned |
| 4 | **Service ACL matrix per user or group** (shell, SFTP, SCP, local/remote forwarding, agent forwarding, tunnels). | VShell service ACLs, Tectia access rules, SFTPGo permissions | `Match` blocks with `PermitTTY`, `AllowTcpForwarding`, `PermitOpen`, `PermitListen`, `AllowAgentForwarding`, `PermitTunnel`, `DisableForwarding`, `ForceCommand`; a users-by-services grid in the manager writes them. | Config now, GUI planned |
| 5 | **Audit logging of file operations and SIEM forwarding.** | VShell, Cerberus, CrushFTP, Syncplify (signed logs) | `LogLevel VERBOSE`; `Subsystem sftp internal-sftp -l INFO` logs open, close, rename and remove per user; events go to the Windows event log (Windows Event Forwarding to a collector) or to `%ProgramData%\ssh\logs` with `SyslogFacility LOCAL0`. The manager already provides the filtered viewer; a hash-chained export for tamper evidence is a candidate. | Config now, viewer done |
| 6 | **Live session monitor with disconnect.** | VShell Monitor, Pragma Session Manager, Syncplify, SFTPGo | Enumerate `sshd-session.exe` processes, resolve the logon user from the process owner, correlate with the TCP peer list, terminate the process to disconnect. | GUI (Sessions tab, 1.1.0) |
| 7 | **Safe configuration lifecycle: validate, back up, roll back, compare effective values, export and import.** | Pragma centralised configuration, VShell import/export, Buru instance cloning | `sshd -t -f <candidate>` before every write, `sshd -T` effective view, timestamped backups, automatic rollback when the service fails to start. The Authentication tab shows what `sshd -T -C` works out for an account, as SYSTEM when group rules apply. Next: an export bundle (configuration, host keys, authorized keys) that can be pushed to other hosts with PowerShell remoting. | GUI done, bundle planned |
| 8 | **IP allow and deny lists and country blocking.** | VShell, Cerberus, CrushFTP, Syncplify, SFTPGo | `Match Address`, `AllowUsers user@cidr`, `DenyUsers`, `from=` in `authorized_keys`; Windows Firewall rule scopes for remote addresses; a country block rule fed from a GeoIP CIDR list, maintained by the manager. | Config now, GUI planned |
| 9 | **Certificate authority wizard and key revocation.** | Tectia, Apache MINA, SFTPGo, wolfSSH | `TrustedUserCAKeys`, `AuthorizedPrincipalsFile` (glob patterns since 10.0), `RevokedKeys` (multiple files since 10.3), `HostCertificate`; the manager could generate a CA, issue short-lived user certificates with principals mapped to Windows groups, and maintain a KRL with `ssh-keygen -k`. FIDO2 hardware keys work today through `sk-*` key types. | Config now, GUI planned |
| 10 | **authorized_keys options editor** (`from=`, `command=`, `restrict`, `permitopen`, `permitlisten`, `expiry-time`, `no-pty`). | Tectia and VShell forced commands, Dropbear `permitopen`/`permitlisten`, SFTPGo | Options are supported by `sshd` today and can be pasted in the Keys tab; a structured editor with per-option fields is the next step. | Config now, GUI planned |
| 11 | **Two-factor login (key plus password) per user.** | Buru per-method policy, SFTPGo, Cerberus, Syncplify | `AuthenticationMethods publickey,password` for everyone or in a rule for a user or group (Authentication tab). Time-based one-time passwords need an authentication provider inside `sshd` (see out of scope). | GUI (Authentication tab, 1.3.0) |
| 12 | **Account lifecycle: lockout, expiry, disable, password policy shown next to SSH users.** | Buru, Cerberus, SFTPGo | Windows already enforces them through `LogonUser`: `net accounts /lockoutthreshold`, `net user X /expires:`, `/active:no`, Group Policy password rules. The manager could surface lock state and expiry per user. | Config now, GUI planned |
| 13 | **Post-transfer and post-login automation** (run script, webhook, mail, move file). | VShell triggers, SFTPGo Event Manager, Cerberus, CrushFTP, Syncplify | Task Scheduler tasks triggered by OpenSSH/Operational event IDs for login, logout and failed authentication; a `FileSystemWatcher` on jail roots or parsing of `internal-sftp -l INFO` close events for "upload complete". | Config now, GUI planned |
| 14 | **Quotas and file-type screens per jail.** | SFTPGo, Cerberus, CrushFTP, Syncplify (soft and hard quotas), VShell type restrictions | NTFS per-user volume quotas (`fsutil quota`), File Server Resource Manager folder quotas with soft and hard thresholds, notifications and file screens on Windows Server; the manager could wrap them per jail root. | Config now (Windows Server) |
| 15 | **Session limits and timeouts per group.** | VShell idle timeout, SFTPGo max sessions, Dropbear maximum session duration | `MaxSessions`, `MaxStartups`, `ClientAliveInterval`, `ClientAliveCountMax`, `ChannelTimeout`, `UnusedConnectionTimeout`, `RekeyLimit`; an absolute session duration limit does not exist in `sshd`, a manager watchdog could end `sshd-session.exe` processes older than N hours. | Config now |
| 16 | **Multiple instances (virtual sites) on one machine.** | Syncplify, Buru instance cloning, VShell multiple ports | Register additional services (`sc create sshd-b binPath= "sshd.exe -f C:\ProgramData\ssh\b\sshd_config"`) with their own port, host keys and log; a clone-instance action in the manager. | Config now, GUI planned |
| 17 | **Host key rotation and algorithm profiles** ("compatible", "modern", "post-quantum only"). | all products with post-quantum support | Generate new host keys while keeping old ones for a grace period so clients with `UpdateHostKeys` migrate; profiles for `KexAlgorithms`, `Ciphers`, `MACs`, `HostKeyAlgorithms`, `PubkeyAcceptedAlgorithms` written by the manager; `sshd -G` audit report. | Config now, GUI planned |
| 18 | **Restricted shell with an admin-defined command allow list.** | Buru `none`/`legacy` shell modes, SFTPGo hash commands, VShell RunAs | Ship a small restricted shell with this repository and select it through `HKLM\SOFTWARE\OpenSSH\DefaultShell` or `ForceCommand`; it would implement `ls`, `cd`, `pwd`, checksums and admin aliases and refuse everything else. | Planned |
| 19 | **Kerberos single sign-on polish.** | Tectia, VShell, Pragma | `GSSAPIAuthentication yes` works with SSPI today and is a box on the Authentication tab (a Kerberos login was not tested here: no domain); the manager could verify the host SPN and warn about the 10.4 GSSAPI fixes while the port is on 10.2. `GSSAPIDelegateCredentials` arrives with 10.3. | Config now |
| 20 | **Bandwidth throttling.** | VShell, SFTPGo, Syncplify | Windows QoS policy on the server port (`New-NetQosPolicy -IPProtocolMatchCondition TCP -IPSrcPortMatchCondition 22 -ThrottleRateActionBitsPerSecond …`) for a global limit; per-user limits are out of scope. | Config now |
| 21 | **Data-at-rest encryption of jail folders.** | SFTPGo, CrushFTP, Syncplify | EFS on jail roots or BitLocker on the volume; the manager could report the state. | Config now |
| 22 | **Metrics and reports.** | SFTPGo (Prometheus), CrushFTP, Cerberus | Aggregate event log counters (logins, failures, bans, sessions) into a text file for `windows_exporter` or a local endpoint; scheduled CSV or HTML reports. | Planned |
| 23 | **Key-pair generator with verification and a login test.** | Bitvise keypair manager, Tectia key generation, VShell key tools | `ssh-keygen` with the passphrase handed over through `SSH_ASKPASS`; verify the key pair, its encryption and its permissions; authorize it in the file `sshd` reads for the account (`sshd -T -C`) and log in with it using a pinned host key. | Done (manager 1.2.0) |
| 24 | **Security self-audit.** | Bitvise and VShell configuration warnings, SFTPGo and Cerberus security dashboards | Check who can change the program folder, `sshd_config`, the `DefaultShell` registry key and the services, who can read the private host keys, and whether SSH is reachable on a public network; warn when Windows servicing points a service at the in-box binary. | Done (manager 1.2.0) |
| 25 | **Login methods per user and group** (password, public key, Kerberos; either one or both required). | Bitvise per-account authentication settings, Buru per-method policy, SFTPGo per-user allowed methods | `Match User` and `Match Group` blocks with `PasswordAuthentication`, `PubkeyAuthentication`, `GSSAPIAuthentication` and `AuthenticationMethods`, written by the Authentication tab in order of precedence; the methods an account gets come from `sshd -T`, run as SYSTEM when group rules apply. Tested with real logins (`--authtest`). | Done (manager 1.3.0) |

## Out of scope for a packaging fork (needs `sshd` source changes)

X.509 certificate authentication (Tectia, VShell, Pragma, wolfSSH); time-based one-time password
and other keyboard-interactive providers; per-user bandwidth or transfer quotas enforced
in-band; pre-upload veto, content filtering or antivirus hooks; HAProxy PROXY protocol;
TPM- or certificate-store-backed host and user keys; cloud or remote-SFTP virtual filesystem
backends and merged virtual filesystems; per-mapping permission flags without a single chroot
root; checkpoint-restart or streaming SFTP; SFTP protocol versions 4 to 6; FTPS, HTTPS and
WebDAV listeners; the experimental composite ML-DSA signature scheme beyond what 10.4 ships;
absolute session-duration limits inside `sshd`; unloading an account's profile when its session
ends (the Windows port calls `LoadUserProfileW` but never `UnloadUserProfile`, so the profile
stays loaded and cannot be deleted before a restart).

These are best requested upstream at
[PowerShell/openssh-portable](https://github.com/PowerShell/openssh-portable) (Windows-specific)
or [openssh/openssh-portable](https://github.com/openssh/openssh-portable).
