# GUI audit — 2026-09-29

Follow-up to the [project audit](AUDIT-2026-09-29.md), focused on the WinForms manager's
actual controls, save paths, asynchronous refreshes, themes, and rendered layouts.

Release follow-up: the fixes are included in Manager 2.2.1 / product 10.5.5.0. PR #12's
[Windows CI](https://github.com/patnawa/openssh_server_pn/actions/runs/36583305646) passed all
148 manager self-tests and the elevated key/authentication suites on Windows Server 2022,
Server 2025, Windows 11 ARM64, and the Server 2022 PowerShell 2.0 installer path.

## Fixed findings

| Area | Reproduced behavior | Fix |
|---|---|---|
| Partner access | Upload/download and Download only could both stay selected; changing back did not undo the choice. | Give both radio buttons the same parent container. |
| Partner login | Password and Public key only could both stay selected. | Group the login radio buttons separately from access choices. |
| Partner setup | The dialog stripped `C:\` to `C:` before passing it to the already-fixed backend. | Preserve absolute drive roots in the dialog result. |
| Setup wizard | An existing disabled firewall rule was enabled without an explicit choice; the summary could say nothing would change. | Add an enable checkbox initialized from the existing rule, retain its profiles, and describe enable/disable changes. |
| Refresh replacement | A timed-out query could overwrite its replacement's results or clear its running flag, admitting a third query. | Tag each refresh with a generation and reject obsolete completions before touching state. |
| Refresh after operations | A query started before foreground work could paint stale data after that work completed. | Invalidate outstanding refresh generations when foreground work begins. |
| Alerts edits | Closing the window did not warn about unsaved alert settings; the tab had no dirty marker. | Snapshot loaded controls, mark edits, and include Alerts in the close warning. Undo and successful reload reset the snapshot. |
| Firewall edits | Unsaved firewall controls were omitted from the close warning. | Track the loaded enabled/profile/port selection and mark the tab and close warning. |
| Default shell option | Settings reloaded the old option before deciding whether to write it, so option-only edits never reached the registry writer. | Capture the option before reloading, write the captured value, refresh after success, and preserve the edit after failure. |
| High contrast | Switching from light to high contrast skipped semantic status-label recoloring. | Include high-contrast transitions in palette application. |
| Dark tabs at larger scale | Painted text grew while native tab hit areas retained default font metrics, causing overlapping captions. | Keep the native tab font synchronized with the painted font, including handle recreation and font changes; release owned GDI fonts. |
| Dark group headings | GroupBox rendered black captions on the dark background even though its inherited ForeColor was correct. | Set the group caption color explicitly for the native themed renderer. |

## Evidence and verification

- Each defect was reproduced before its fix. Tests drive real controls or the real save/refresh
  method; the group-heading test checks rendered pixels, not only the ForeColor property.
- Added 15 tests across `AuditDialogTests`, `AuditStateTests`, and `AuditGuiTests`.
  The full unit suite passes **100 tests**, up from 85 after the first audit.
- The complete shell-save regression uses a scratch configuration, a harmless temporary
  validator executable, and an injected registry writer. It confirms the value reaching the
  writer without changing the machine's shell.
- Refresh races use controlled worker completion order and the WinForms message loop.
- Generated screenshots for all tabs and sample dialogs in light mode and dark mode at 150%.
  Inspected the affected partner dialog, wizard, dashboard, tab strip, and group headings;
  the final dark dashboard shows readable separated tabs and light group captions.
- Existing window self-tests cover 100%/150% layouts on a 1024 x 768 window, accessibility names,
  theme switching, validation, rejected saves, reloads, and unsaved changes across tabs.
- Rebuilt the tracked manager executable with warnings treated as errors. No release version
  was assigned during the audit itself; the later release follow-up is recorded above.

## Limits

This is off-screen WinForms interaction and rendering, not a physical multi-monitor DPI test
or a screen-reader session. Native desktop automation is unavailable in this session. No live
firewall, registry, account, service, or server configuration changes were made by these tests.

The full non-elevated self-test still has the same three failures involving protected host
keys and security inspection; eight elevated checks explicitly skip. Elevated end-to-end save,
firewall, account, and SSH-login verification remains required before release. The native
Windows date picker and disabled-button rendering retain platform-specific styling.
